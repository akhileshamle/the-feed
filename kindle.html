Friday: Fermi estimation

Break an unknown quantity into 3-5 factors you can guess, then multiply them. Individual guesses may be off, but errors tend to partly cancel, so you land within a factor of 2-3 of the truth.

Problem: A coffee shop near a train station wants to know how many cups of coffee it must sell per year to justify a second espresso machine. First, estimate the cups a single busy city-centre café sells per year using these guesses:

  • Customers per hour in open hours: 30
  • Open hours per day: 10
  • Share of customers who buy at least one coffee: 60%
  • Open days per year: 350

How many cups per year, roughly? Then, if each cup brings £1.80 gross margin, what is the yearly gross margin from coffee?

Try it first:

  • Multiply customers per day first, then the coffee share.
  • Round to friendly numbers (e.g. 350 ≈ 3.5 x 100) and track powers of ten separately.
  • Margin is just cups times £1.80; round £1.80 to £2 for a sanity check, then adjust.

Why it matters: Quick order-of-magnitude estimates let you sanity-check a business case, a capacity plan or a quote before anyone builds a spreadsheet.

Answer

  • Customers per day: 30 x 10 = 300
  • Coffee buyers per day: 300 x 0.6 = 180 cups
  • Per year: 180 x 350 = 63,000 cups
  • Margin: 63,000 x £1.80 = £113,400 (sanity check: 63,000 x 2 = £126,000, slightly higher, as expected)

So about 63,000 cups and roughly £110k gross margin per year.

Friday: Feedback loops (dx/dt = kx; k>0 compounds, k<0 stabilizes)

The idea: A feedback loop means the current size of something changes its own rate of growth. When k>0, more begets more (compounding, runaway). When k<0, any drift away from a target triggers a push back toward it (a thermostat).

Question: A team's on-call alerts create fatigue. Each unresolved alert causes people to ignore the next ones, which leads to more unresolved alerts. Is k positive or negative? What single change flips its sign?

Real-life application (software engineering): Test suites with flaky tests. A flaky failure teaches people to re-run instead of investigate, so they trust the suite less, write fewer tests, and the flakiness goes unfixed, which creates more flakes. Teams that quarantine a flaky test within 24 hours turn k negative: the failure gets a fast, forced response, and the suite pulls back toward healthy.

2-minute exercise: Pick one loop in your life right now (sleep, inbox, savings, a codebase). Write two lines: "More X causes more Y, which causes more X" and where the loop currently sits (k>0 or k<0). Then name one lever that would flip it.

Log it: date, concept, my answer, what I applied.

Answer

k is positive: ignored alerts breed more ignored alerts, so the problem compounds. To flip the sign, make every alert actionable and owned. Delete or tune any alert that no one acts on, and require a response for the rest. Fewer, trusted alerts mean a missed one gets noticed and corrected, so deviation shrinks (k<0).

Friday: Debugging and production (launch watchdog regression)

Why this matters: Watchdog terminations at launch never show up as normal crashes in your SDK dashboard, so a regression can quietly churn users for days. On older devices a few hundred milliseconds of extra main-thread work at launch can turn into a kill rate that tanks retention.

Scenario: Version 7.3 is at 20% of a phased release. Xcode Organizer shows 0x8badf00d terminations up 4x, concentrated on A12-class devices with large datasets. You can't reproduce it locally. The release added a synchronous keychain-to-SQLite token migration in application(_:didFinishLaunchingWithOptions:) and a new analytics SDK initialised at launch. Any fix needs a new binary, and expedited review is roughly 24 hours. Pausing the phased release leaves the 20% on the bad build.

Recall first:

  1. Which data sources can locate the blocking frame without a repro?
  2. What does pausing a phased release actually stop, and what doesn't it stop?
  3. What would you do in the next hour and in the hotfix, and why?

Answer

Decision: Pause the phased release now. Pull the MXAppLaunchDiagnostic and MXHangDiagnostic call stacks from MetricKit, plus the Organizer termination logs, to confirm the frame. If the SDK init is remotely gateable, kill it with a flag. In the hotfix, move the migration off the main thread behind an async gate and request expedited review.

Rejected:

  • Removing the app from sale: it hits everyone.
  • Waiting for a repro: the field data already contains the stack.
  • Full rollback: the App Store doesn't support it.

Main risk: Once the migration is async, code can read tokens before the migration finishes, which causes spurious logouts.

Common mistake: Assuming the pause protects users. It only stops automatic updates. Manual updates and new installs still get 7.3.

actor TokenStore {
    private var ready: Task<Void, Error>?
    func start() { ready = Task.detached(priority: .userInitiated) { try Migrator.run() } }
    func token() async throws -> String {
        try await ready?.value
        return try read()
    }
}
