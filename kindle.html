Friday: Feedback Loops (dx/dt = kx)

The idea When the output of a system feeds back into its own rate of change, you have a loop. If k is positive, growth causes more growth, so small things compound into big ones. If k is negative, the system pushes back against change and settles toward a set point, the way a thermostat holds a room's temperature.

Today's question An unanswered email backlog grows about 5% per day, because each delayed reply brings follow-ups and "just checking in" messages. If you do nothing, roughly how many days until the backlog doubles?

Real-life application: software engineering A retry storm is a k>0 loop. A service slows down, clients time out and retry, the retries add load, and the service slows down even more. The usual fix is exponential backoff with jitter, which is a k<0 loop: the more failures a client sees, the longer it waits before trying again, so the load falls and the service recovers. When a system spirals, find the loop first and then change the sign of k.

2-minute exercise

  1. Write down one thing in your life that is getting steadily better or worse, such as savings, fitness, inbox size or a relationship.
  2. Mark its loop as k>0 (it compounds) or k<0 (it stabilizes).
  3. Name the variable that feeds back into itself.
  4. Name one small action that would flip the sign or change the size of k this week.

Log it: date, concept, my answer, what I applied.

Answer

Use the rule of 70: doubling time ≈ 70 / (growth rate in %). At 5% per day, that is 70 / 5 ≈ 14 days. The exact figure is ln2 / 0.05 ≈ 13.9 days. After four weeks the backlog would be about 4× its size today. Clearing even a small part of it every day turns k negative and stops the growth.

Friday: Trees (DFS, BFS, recursion)

When to reach for this pattern: Use it when the answer for a node depends on its subtrees or on its path from the root, so you can pass state down or return results up.

Problem: Maximum Ancestor Difference Given the root of a binary tree, return the largest value of |a.val - b.val|, where node a is an ancestor of node b.

Example:

      4
     / \
    1   7
         \
          12

The pairs are (4,1)=3, (4,7)=3, (4,12)=8 and (7,12)=5, so the output is 8.

Recall first

  1. What is the brute force, and what does it cost?
  2. For any node, which two values on its root-to-node path can produce the largest difference with it?
  3. What are the time and space targets?

---

Answer

The brute force runs a DFS from every node and compares it with all of its descendants. That is O(n²) on a skewed tree. The key observation is that a node's best difference with any ancestor uses either the smallest or the largest value on its root path. So pass lo and hi down the recursion and update them at each node. When you reach a null child, the path is complete, so return hi - lo. Take the maximum over all paths.

func dfs(node, lo, hi) -> Int:
    if node == nil: return hi - lo
    lo = min(lo, node.val)
    hi = max(hi, node.val)
    return max(dfs(node.left, lo, hi),
               dfs(node.right, lo, hi))

answer = dfs(root, root.val, root.val)
  • Time: O(n), because each node is visited once.
  • Space: O(h) for the recursion stack. That is O(log n) when the tree is balanced and O(n) when it is skewed.

Friday: Fermi estimation

Break a number you can't look up into 3–5 factors you can guess, then multiply them. Each guess may be off, but the errors tend to cancel, so the result usually lands within a factor of 2–3 of the truth.

Problem: Your iOS team has 8 engineers. Each pushes branches that trigger a CI build of about 12 minutes. Roughly how many engineer-hours per year does the team spend waiting on CI builds, unable to do focused work?

Try it first:

  • Guess how many builds one engineer triggers on a typical workday.
  • Not every minute of a build is lost. Guess what fraction of build time someone is actually blocked.
  • Use about 230 working days in a year.

Why it matters: A rough number like this lets you argue for a faster CI machine or build caching in money terms, without waiting for a dashboard.

Answer

One reasonable estimate (your guesses can differ):

  • Builds per engineer per day: 6
  • Team builds per day: 8 × 6 = 48
  • Build minutes per day: 48 × 12 = 576 min ≈ 9.6 h
  • Fraction of that time someone is blocked: 1/3, so 9.6 / 3 ≈ 3.2 h/day
  • Per year: 3.2 × 230 ≈ 736 h ≈ 740 engineer-hours

That is about 18 full 40-hour work weeks a year. At about $100 per engineer-hour, it costs around $74k a year. Halving build time would save about $37k a year, which is more than a fast CI Mac costs.
